# Editor frontend modules

> **🔧 Internal engineering record — not user documentation.** The per-module
> map of the editor frontend (`resources/packages/app/editor/*.js` +
> `resources/packages/web/runtime/*.js`). Indexed from
> [CLAUDE.md](../CLAUDE.md); the working rules for editing these files live in
> the `graphden-ui` skill.

| File | Purpose |
|------|---------|
| `editor-state.js` | Global variables, constants, `BUILD_HASH` placeholder |
| `editor-canvas-keys.js` | Keyboard navigation over the graph canvas. Movement follows the EDGES, not the screen: `→`/`l` steps into an argument (outgoing edge), `←`/`h` back to the consumer, `↑↓`/`kj` between siblings of the same consumer; `Enter` opens the card in the inspector by driving its own click handler. Focus and the viewport are coupled by hand — `#graph-layer` is positioned by a CSS transform, so there is no scroll box and `scrollIntoView` does nothing; `ensureNodeVisible` writes `viewport.pan` directly, and only when the target is actually off-screen. Its MutationObserver watches `#graph-container` with `subtree: true` rather than `#graph-layer`: the layer is created on the first render, i.e. after this module installs. |
| `editor-tree-keys.js` | Keyboard navigation over the Explorer tree (WAI-ARIA tree pattern) — arrows move, Right/Left expand and collapse, Enter opens, Home/End jump. All listeners are DELEGATED and the current row is remembered as a KEY (fn id / namespace path / compare-mode ghost fn id) rather than an element, because `updateEntityList` rebuilds the tree with `innerHTML = ''` — and selecting a fn calls it, so a naive roving tabindex loses both the tab stop and the focus on the first keystroke. A MutationObserver restores both afterwards, but only when focus was inside the tree beforehand (otherwise a background rebuild would yank the keyboard away from wherever the user actually was). The tree renders FLAT — a namespace header and its `.ns-children` are siblings — so depth comes from an explicit `aria-level` stamped by editor-sidebar.js, not from the DOM. |
| `editor-shortcuts.js` | The keyboard-binding registry and its dispatcher. `registerShortcut({id, keys, leader, when, run, description, group})` is the only place a binding is declared; `Space` opens a which-key menu built from the registry (a real listbox, so it doubles as the screen-reader command surface) and `?` renders the cheatsheet from the same source, so neither can drift from what is bound. Listens on **window**, not document: both are bubble-phase, but this module loads early, so a document listener would run BEFORE the dialogs' own handlers and see `defaultPrevented` still false — window is the last stop in the bubble path. Bare keys are scarce and deliberate (`/`, `+`, `-`, `?`); everything else lives behind the leader, leaving the letter keys free for canvas navigation. The `Surfaces` group (`Space v` + `b`/`s`/`o`/`p`) reaches Build / Settings / Organization / Platform (the latter behind the same capability gate as its menu row). |
| `editor-a11y.js` | Accessibility primitives shared across modules. `window.gdAnnounce(msg, {assertive})` — the polite/assertive live regions used to announce state that changes without moving focus (fn selected, branch switched). Also `prefersReducedMotion()` (live `matchMedia` query, not cached — the OS setting can flip while the page is open) and `scrollIntoViewMotionSafe()`. Loaded second, right after `editor-state.js`, because the graph tween asks it whether it may animate before its first frame. The declarative half of reduced-motion lives in the `@media (prefers-reduced-motion: reduce)` block at the END of `editor-styles.css`; this module covers only what CSS cannot reach (the RAF tween, smooth scrolling). |
| `web/runtime/graphden-popover.js` | Platform-shared popover primitives (NOT editor-specific) — `anchorBelowClamped` viewport-clamped positioner + `installPopoverDismiss` outside-pointerdown/Esc handler (options `trapFocus` / `getReturnFocus` add the keyboard half), plus the focus primitives every dialog needs: `focusableWithin` / `focusSafely` / `focusIntoDialog` / `returnFocusTo` / `installTabTrap` / `setSiblingsInert`. Focus ENTRY and RETURN stay explicit calls rather than being inferred from `getAnchor`: dialogs also close through paths that never reach the dismiss handler (× button, Cancel, submit), and one caller passes a neighbouring popover as its anchor. Pure DOM (no cy/graphData/editor-state); bundled into BOTH the editor bundle and the standalone `/assets/graphden-runtime.js` (see `:_graphden-runtime-js-paths`) so user-composed pages can build info/form popovers too. |
| `editor-busy.js` | Visible feedback for multi-step user actions (reparent / extend / delete cascades) — `withBusy(opKey, label, fn)` helper + bottom-centre banner |
| `editor-prefs.js` | Theme + sidebar-collapsed prefs (localStorage); the collapsed-state left-edge expand tab (`installFloatingExpandBtn`) that also hosts the non-default-branch badge |
| `editor-feedback.js` | Feedback ("Report a problem") — uncaught-JS-error ring buffer, the report form modal (`window.openFeedbackForm`) with a transparent attach-checkbox list (build/env, console errors, opt-in location, opt-in error-log), and delivery straight from the browser to the intake URL announced by `GET /api/feedback/config` (env-controlled; empty = feature hidden, `window.feedbackEnabled`). Sends as `text/plain` to stay a CORS simple request; on unreachable intake offers a download-JSON + GitHub-issue fallback. Entry points: shell menu (`editor-auth.js`) and the Errors panel footer (`editor-errors.js`). |
| `editor-auth.js` | `authFetch`, `isAuthenticated`, login popover; the account chip's SHELL MENU (`openShellMenu`) — the single entry to Settings / Organization / Platform (capability-gated) plus the session actions for every auth mode. The menu is a real ARIA menu: focus enters on open, ↑ ↓ Home End walk the `menuitem`s, Escape/Tab close and return focus to the chip, and the chip carries `aria-haspopup`/`aria-expanded` |
| `editor-org-switcher.js` | Top-bar org-switcher chip for multi-org accounts (Slack-style, Track B/C). Fetches `GET /api/memberships` (tenancy auth-routes; session-cookie auth, no `window.API` key) and mounts a chip in `#org-mount` only when the account belongs to MORE THAN ONE org. Picking another org NAVIGATES to that org's subdomain origin (`<org>.graphden.dev`); on a single-host dev instance the fallback is `POST /api/switch-org` (sets the `gd_org` selector cookie + reloads). Skips entirely when the accounts addon is absent (`window.gdAccountsReady` boot probe). |
| `editor-branches.js` | Branch-aware fetch wrap (every `/api/*` call carries `X-Graphden-Branch`), current-branch state (URL `?branch=` + localStorage), Explorer branch chip + popover, the collapsed-edge branch badge (`gdSyncEdgeBranchBadge` — branch name on the expand tab when ≠ main), the protected-branch ⛨ mini-menu (`openBranchPolicyMenu` → POST `/api/branches/:ref/policy`) + the Advanced create policy select (both tenancy-gated via `body.gd-tenancy`), the per-row ⋯ overflow menu (`toggleBranchMoreMenu` — labeled review/propose/protection/policy/delete items — 💬 Review & comments first; Δ/✅/⇢ stay inline with instant `data-tip` tooltips; every row op resolves its `/api/branches/:ref/*` path through `branchRefFrom` — the row's `data-branch-id` — so a slash-named branch, e.g. the hub's `push/<x>`, stays operable) and the ⚙ protection menu with its 0…3 segmented required-approvals control (`openProtectionMenu`), `switchToBranch` reloads to invalidate caches, conflict-resolution modal for `:reason :merge-conflict` merge responses, and the popover's **Hub** section wiring (`wireHubSyncSection` — the partial renders the section only when `GRAPHDEN_HUB_URL` is set; JS removes it when `window.API` lacks the optional registry package's `/api/sync/*` routes, and drives ⇡ Push `POST /api/sync/push` / ⇣ Pull `POST /api/sync/pull`) |
| `editor-diff-render.js` | The shared client renderer of diff-view GROUPS (`gdDiffRenderGroups` / `gdDiffRenderGroup` / `gdDiffRenderEntry` / `gdDiffMarkerEl` / `gdDiffCommentBtnEl`) — the DOM the retired server partial used to emit, consumed by three surfaces: the Review dialog's "What changed" list, per-suggestion Δ previews and the inspector diff panel. Pure DOM building (createElement/textContent, data-anchor-* hooks for the thread attacher); knows nothing about compare-mode state. Loads before branch-diff/diff-mode. |
| `editor-branch-diff.js` | The 💬 REVIEW DIALOG (⋯ menu → "Review & comments" on a branch row, or the compare-mode chip menu) — `showReviewDialog(sourceName, sourceRef?)` frames the source against its BASE branch and owns the branch CONVERSATION: a collapsible "What changed" summary (client-rendered by `gdDiffRenderGroups` from `GET /api/branches/:ref/diff-view?against=`, read-only, auto-open for small diffs), the comment thread (`initDiffConversation` — anchored orphans get an `[on fn …]` chip; also exported as `gdDiffAttachThreads` for the inspector diff panel's anchored-only threads), and the Suggestions section (proposed child branches of the source → lazy Δ preview / one-click apply-merge / "+ Suggest a change" fork-and-switch). Ref-path calls (comments, diff-view, apply-merge) prefer the branch ID over its name so slash-named branches stay operable. |
| `editor-diff-mode.js` | COMPARE MODE — THE diff surface (no modal). `gdEnterDiffMode(branch)` (the Δ on a branch-popover row — lit on the picked branch, click again to exit; persisted in localStorage `graphden.diffAgainst`, restored on boot, auto-dropped when you land on the compared branch) fetches `GET /api/branches/:current/diff-view?against=…` (the grouped `:diff-branches-view` payload, by resolved branch IDs) and annotates the editor: `.gd-diff-badge` +/−/± on changed Explorer fn rows, `.gd-diff-ns-badge` aggregate counts on namespace headers (re-applied via a MutationObserver on `#entity-list`, with opportunistic ≥20s refetch), the `#gd-diff-lens` LENS BAR under the Explorer kind-chips (`gdDiffSetLens` — "only changed" tree filtering via `.gd-diff-lens-hidden`, plus added/modified/only-there, substantive-only, effects-touched-only and 💬-notes toggles; persisted as `graphden.diffLens`), 💬 markers on tree rows whose changes carry anchored review comments (counts from the compared branch's `/comments`, attributed to the owning fn through the diff-view groups), a `Δ vs <branch> · N` chip beside the branch chip counting the changed fns (`visible/total` while a lens filter is on; click = the review-cockpit menu: 💬 Review & comments / 📤 propose-current / ⇢ merge-compared-in; × = exit), persistent Δ rings on changed args (`gdDiffSlotsForFn`, consulted by `editor-overlay-arg.js`), card-level rings on changed fns (`gdDiffModeCardInfo`, consulted by `editor-overlay-fn.js`), GHOST rows for fns existing only on the compared branch (injected into expanded `.ns-children` groups; click = switch there), the INSPECTOR DIFF PANEL (`gdDiffRenderInspectorSection`, called by `editor-shell.js` after every inspector render — change marker, per-field `old → new` entries, effects-delta chip, 📍 badge, per-element 💬 anchored threads via `gdDiffAttachThreads`) and per-fn effect-delta annotations — the FULL per-branch effect-set comparison (`gdDiffEffectSetDelta` over two branch-scoped `/api/types` fetches; the registry is branch-scoped as of 2026-08-31), falling back to the structural `gdDiffEffectsTouched` signal for fns unnamed on either side. Annotations only — data routing stays on the current branch, so you keep working with the lens on. **UX-v4 (2026-09-03) — the diff as a GRAPH:** `∿` CHANGED-INSIDE marks (`gdDiffAffectedInfo` — the server's `:affected` walk over the compiler's reverse-deps: own rows equal, an ancestor / ref target / type in the diff; `inside` lens toggle; dashed card ring + `.fn-diff-inside-badge` whose click reveals the ancestor IN the card via `expansionState` or opens the ref target — `gdDiffRevealVia`), node-level "there" values drawn ON the node (`gdDiffSlotDetails` → `gdDiffWasEl`: `.arg-diff-was` under a changed arg / on an unbound placeholder, struck-through; `.arg-overlay-diff-added` for bound-here-only; `gdDiffAppendFnStrip` → `.fn-diff-was` for a rename / description edit), and a per-fn DIGEST under each changed Explorer row (`gdDiffSummaryParts` → `.gd-diff-summary`, "a: 1 (there 2) · b → :x (there :y)"; `∿ via <fn>` on changed-inside rows; namespace badges add `∿n`). |
| `editor-diff-ghost.js` | Compare mode's GHOST SUBTREES (UX-v4) — for an arg bound to a DIFFERENT fn on the compared branch (a replaced ref), the other side is drawn beside the card: `gdDiffGhostsRender(container)` (end of `createNodeOverlays`) finds the anchors (value / placeholder arg nodes by owning fn + slot; a ref bound here by its `argName` edge → the target card), fetches the compared branch's `?scope=subtree` for the there-ref (explicit `X-Graphden-Branch`, cached per branch+fn), and lays a read-only column of dashed mini-cards (`.gd-ghost-cluster` / `.gd-ghost-card`, root then its refs breadth-first, capped at 8 cards × 6 rows, folded when large) at the anchor's right in GRAPH coordinates inside the graph layer, joined by a dashed `.gd-ghost-link` elbow; `gdDiffGhostsSync()` (from `syncOverlayGeometry`) re-anchors clusters after a tween / drag.
