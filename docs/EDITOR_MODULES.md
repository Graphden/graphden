# Editor frontend modules

> **🔧 Internal engineering record — not user documentation.** The per-module
> map of the editor frontend (`resources/packages/app/editor/*.js` +
> `resources/packages/web/runtime/*.js`). Indexed from
> [CLAUDE.md](../CLAUDE.md); the working rules for editing these files live in
> the `graphden-ui` skill.

| File | Purpose |
|------|---------|
| `editor-state.js` | Global variables, constants, `BUILD_HASH` placeholder |
| `editor-shortcuts.js` | The keyboard-binding registry and its dispatcher. `registerShortcut({id, keys, leader, when, run, description, group})` is the only place a binding is declared; `Space` opens a which-key menu built from the registry (a real listbox, so it doubles as the screen-reader command surface) and `?` renders the cheatsheet from the same source, so neither can drift from what is bound. Listens on **window**, not document: both are bubble-phase, but this module loads early, so a document listener would run BEFORE the dialogs' own handlers and see `defaultPrevented` still false — window is the last stop in the bubble path. Bare keys are scarce and deliberate (`/`, `+`, `-`, `?`); everything else lives behind the leader, leaving the letter keys free for canvas navigation. |
| `editor-a11y.js` | Accessibility primitives shared across modules. `window.gdAnnounce(msg, {assertive})` — the polite/assertive live regions used to announce state that changes without moving focus (fn selected, branch switched). Also `prefersReducedMotion()` (live `matchMedia` query, not cached — the OS setting can flip while the page is open) and `scrollIntoViewMotionSafe()`. Loaded second, right after `editor-state.js`, because the graph tween asks it whether it may animate before its first frame. The declarative half of reduced-motion lives in the `@media (prefers-reduced-motion: reduce)` block at the END of `editor-styles.css`; this module covers only what CSS cannot reach (the RAF tween, smooth scrolling). |
| `web/runtime/graphden-popover.js` | Platform-shared popover primitives (NOT editor-specific) — `anchorBelowClamped` viewport-clamped positioner + `installPopoverDismiss` outside-pointerdown/Esc handler (options `trapFocus` / `getReturnFocus` add the keyboard half), plus the focus primitives every dialog needs: `focusableWithin` / `focusSafely` / `focusIntoDialog` / `returnFocusTo` / `installTabTrap` / `setSiblingsInert`. Focus ENTRY and RETURN stay explicit calls rather than being inferred from `getAnchor`: dialogs also close through paths that never reach the dismiss handler (× button, Cancel, submit), and one caller passes a neighbouring popover as its anchor. Pure DOM (no cy/graphData/editor-state); bundled into BOTH the editor bundle and the standalone `/assets/graphden-runtime.js` (see `:_graphden-runtime-js-paths`) so user-composed pages can build info/form popovers too. |
| `editor-busy.js` | Visible feedback for multi-step user actions (reparent / extend / delete cascades) — `withBusy(opKey, label, fn)` helper + bottom-centre banner |
| `editor-prefs.js` | Theme + sidebar-collapsed prefs (localStorage); the collapsed-state left-edge expand tab (`installFloatingExpandBtn`) that also hosts the non-default-branch badge |
| `editor-feedback.js` | Feedback ("Report a problem") — uncaught-JS-error ring buffer, the report form modal (`window.openFeedbackForm`) with a transparent attach-checkbox list (build/env, console errors, opt-in location, opt-in error-log), and delivery straight from the browser to the intake URL announced by `GET /api/feedback/config` (env-controlled; empty = feature hidden, `window.feedbackEnabled`). Sends as `text/plain` to stay a CORS simple request; on unreachable intake offers a download-JSON + GitHub-issue fallback. Entry points: shell menu (`editor-auth.js`) and the Errors panel footer (`editor-errors.js`). |
| `editor-auth.js` | `authFetch`, `isAuthenticated`, login popover; the account chip's SHELL MENU (`openShellMenu`) — the single entry to Settings / Organization / Platform (capability-gated) plus the session actions for every auth mode |
| `editor-org-switcher.js` | Top-bar org-switcher chip for multi-org accounts (Slack-style, Track B/C). Fetches `GET /api/memberships` (tenancy auth-routes; session-cookie auth, no `window.API` key) and mounts a chip in `#org-mount` only when the account belongs to MORE THAN ONE org. Picking another org NAVIGATES to that org's subdomain origin (`<org>.graphden.dev`); on a single-host dev instance the fallback is `POST /api/switch-org` (sets the `gd_org` selector cookie + reloads). Skips entirely when the accounts addon is absent (`window.gdAccountsReady` boot probe). |
| `editor-branches.js` | Branch-aware fetch wrap (every `/api/*` call carries `X-Graphden-Branch`), current-branch state (URL `?branch=` + localStorage), Explorer branch chip + popover, the collapsed-edge branch badge (`gdSyncEdgeBranchBadge` — branch name on the expand tab when ≠ main), the protected-branch ⛨ mini-menu (`openBranchPolicyMenu` → POST `/api/branches/:ref/policy`) + the Advanced create policy select (both tenancy-gated via `body.gd-tenancy`) (list / create / switch / Δ diff / ⇢ merge / × delete), `switchToBranch` reloads to invalidate caches, conflict-resolution modal for `:reason :merge-conflict` merge responses, and the popover's **Hub** section wiring (`wireHubSyncSection` — the partial renders the section only when `GRAPHDEN_HUB_URL` is set; JS removes it when `window.API` lacks the optional registry package's `/api/sync/*` routes, and drives ⇡ Push `POST /api/sync/push` / ⇣ Pull `POST /api/sync/pull`) |

| `editor-tour-cleanup.js` | Undoing what a lesson made. A step declares `:creates {:type … :name …}`; this file both REPORTS what still exists (`_tourSurvivors` — the end-of-tour offer lists it) and deletes it (`_tourDeleteCreated`). Four types: `fn`, `ns`, `branch`, `package-version`, and both halves must know all four — a type the deleter knows and the reporter does not is a row the reader is never told about. Order matters: fns (NEWEST first, because the server refuses to delete a fn something still references), then unpin and withdraw published versions (a pin left pointing at the materialised copy the namespace pass deletes is what makes the NEXT install 404), then namespaces (cleared of contents first, or the delete 409s). Fns resolve through the SEARCH endpoint, not the lexical graph — the client holds only the selected subtree, and an absent row reads as “already gone”. Returns `{failed}` rather than swallowing: an unconditional “deleted” toast over a refused delete is a lie the reader only discovers by hand later. |
| `editor-tour.js` | Interactive tutorial overlay — spotlight ring + step popover for the guided in-editor lessons. Lesson CONTENT (texts, spotlight target selectors, declarative completion checks) is served from the graph at `GET /api/tour` (`app.tour/_tour-lessons`); this module only interprets it: positions the spotlight, polls the checks against the lexical `graphData`/`lookups`, tracks what the lesson created (step `:creates`) and offers soft-delete cleanup at the end. Sidebar-anchored steps auto-expand a collapsed Explorer. Mid-lesson state survives reloads in `localStorage` (`graphden.tour`) — which is what lets a branch-switching step (lesson 19 forks a branch, `switchToBranch` reloads the page) resume on the other side. Split 2026-08-21: the completion checks live in `editor-tour-checks.js`, the undo pass in `editor-tour-cleanup.js`, the catalogue in `editor-tour-picker.js` (all four load in that order); this file is the ENGINE — spotlight placement, step rendering, Back / Pause, state persistence, and the end-of-tour dialogs. Below 700px CSS width every tour surface (step, catalogue, dialog) docks to the bottom edge as a sheet (`.gd-tour-sheet`) and the Explorer reserves its height as bottom padding, because a 360px popover on a 390px screen covers the panel the step is pointing at. At any width the popover is placed clear of the PANEL its target lives in, not merely of the target: 35 steps anchor into the Explorer, and 16px to the right of a 250px filter box is straight over the rows the step tells the reader to click. Two reader-state traps are cleared once per step — a collapsed Explorer, and a kind LENS that hides the very fn the step's check names (`_tourFnRowHidden`). Escape belongs to whatever is on top: a handler that closes something on Escape calls `preventDefault` to say so, and the tour ends only on an unconsumed one. Dialog prose is graph content too (`:copy` in `app.tour/_tour-lessons`, read through `_tourCopy` with an English fallback). Step bodies carry two inline marks (`_tourRenderBody`): `[[Label]]` renders a keycap-style chip for a UI element the reader must press, `` `text` `` a monospace click-to-copy chip for text they must type; plain text passes through verbatim (unit-tested in `tools/runtime-test/tour-body-markup.test.js`). A step may carry `:targets` — an ordered selector chain for actions that pass through transient UI (⋯ menu, literal-vs-ref chooser, fn picker): the spotlight follows the DEEPEST selector currently visible (`_tourEffTarget`), so the menu item a step names is ringed the moment its menu opens. The spotlight itself is TWO stacked elements over one rect: `#gd-tour-dim` carries the scrim at z-index 290 (below every transient surface — an open menu floats bright), `#gd-tour-spot` carries the accent ring at 10050 (above them — a chain stage inside an open menu stays visible); both are pointer-events-none. Sidebar-anchored steps auto-expand a collapsed Explorer and scroll an off-screen target into view (a spotlight below the fold is the same dead end as a missing one), and the popover never covers its own target. A lesson that binds into a freshly extended child MUST gate on `selected` first — without it the spotlight can ring the PARENT's placeholder (the 2026-08-20 package-fn poisoning). Drift guard: `tools/browser-test/edit-tutorial-tour.test.js` walks every lesson step against the live editor. |
